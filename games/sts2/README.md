# Slay the Spire 2: reference material

- `decomps/` contains decompiled C# of the workshop mods installed on this PC. It's
  **local only and git-ignored**: it's other authors' code. Read it to learn their
  patterns and item ids, but don't copy it into our mod or commit it.
- `mod_content.json` lists every relic, card and potion those mods define, with the id
  the game uses (e.g. `RELIC.ZONETHESPIRE-PRISM_CLOUD`). It's generated by
  `scan_content.py` and also git-ignored.

The base game's own decompiled source is a separate GDRE Tools project
(`Desktop\Slay the Spire 2`). Look there for `ModelDb`, `RelicCmd`, and the dev console
commands in `src/Core/DevConsole/ConsoleCommands/`.

## What was learned

- Mods add an item as a class with a pool attribute, e.g.
  `[Pool(typeof(EventRelicPool))] class PrismCloud : CustomRelicModel` (BaseLib).
- Give an item with `await RelicCmd.Obtain(relic.ToMutable(), player)`. This is the same
  call the game's `relic add <id>` console command uses.
- Ids: `Category.Entry`. `Entry` is `Slugify(ClassName)` (`PrismCloud` → `PRISM_CLOUD`).
  BaseLib then prefixes the mod's root namespace for its custom models
  (`ZONETHESPIRE-PRISM_CLOUD`), unless the class sets `[CustomID("...")]`.
- `ModelDb.AllRelics` / `AllCards` / `AllPotions` include modded items. Our mod should
  read these at runtime instead of hard-coding ids.

## Regenerating

Needs the .NET SDK. `ilspycmd` 9.1 works with SDK 9 (newer versions need SDK 10).

```powershell
dotnet tool install ilspycmd --version 9.1.0.7988 --tool-path .tools
$ws   = "C:\Manual_D\Steam\steamapps\workshop\content\2868840"
$game = "C:\Manual_D\Steam\steamapps\common\Slay the Spire 2\data_sts2_windows_x86_64"
# one mod (repeat per DLL; -r points at assemblies it references):
.tools\ilspycmd.exe -p -o games\sts2\decomps\ZoneTheSpire -r $game -r "$ws\3737335127\BaseLib" "$ws\3806787309\ZoneTheSpire.dll"
python -I games\sts2\scan_content.py games\sts2\decomps > games\sts2\mod_content.json
```

Mods with several builds (`HextechRunes`, `STS2-RitsuLib`) were decompiled from their
largest DLL variant only.
